## 2025-05-14 - SSRF/LFI vulnerability in Browser MCP URL navigation tool
**Vulnerability:** The `navigate` tool in `src/tools/common.ts` accepted any user-provided URL without validating its protocol scheme.
**Learning:** Even though Zod schema validation was likely enforcing a string type, it failed to enforce a safe protocol. When passing arbitrary URLs directly to a browser automation framework, failing to restrict the protocol scheme allows an attacker to supply `file://` (reading local system files), `javascript:` (executing arbitrary code in the browser context), or `data:` payloads. Additionally, wrapping `new URL()` in a `try...catch` is critical as it throws a `TypeError` for malformed inputs that can crash the process if unhandled.
**Prevention:** Always explicitly validate and allowlist URL protocols (e.g., ensuring `new URL(url).protocol` is `http:` or `https:`) before passing them to the browser or external request engines. Handle `try...catch` around URL instantiation and validate both that the parsed scheme is allowed and that the schemeless URLs properly default to `https://`.
